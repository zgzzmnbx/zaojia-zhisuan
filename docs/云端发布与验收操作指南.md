# 造价智算云端发布与验收操作指南

## 1. 用途与原则

本指南用于把造价智算的已验证本地版本发布到现有云服务器，并完成可回滚、可验收、可追溯的上线闭环。执行线程必须直接完成检查、打包、上传、切换、验收、文档回写和 Git 推送，不得只输出方案。

发布必须遵守以下原则：

1. 先检查，后上传；先准备回滚点，后切换版本。
2. 发布包不携带密码、密钥、运行数据库、机器人秘密或 `.env.local`。
3. 新发布目录继承上一版本的运行时秘密和数据，不能用发布包覆盖。
4. 云端主服务固定使用 `1285`；本机开发默认使用 `8000`。
5. 第二层机器人保持发布前的启用状态。关闭状态不得因发布被强制拉起。
6. 任何门禁失败都不得宣称上线成功；切换后健康检查失败应立即回滚。
7. 中文目录发布只使用 UTF-8 保真的 `tar.gz`，不得使用 Windows ZIP 交给 Linux `unzip`。

## 4. SSH 凭据管理

本机凭据文件：

```text
Codex-Temp/runtime/cloud-deployment-credentials.json
```

字段固定为：

```json
{
  "host": "服务器地址",
  "port": 22,
  "username": "SSH 账号",
  "password": "SSH 密码"
}
```

安全要求：

- 该文件位于 Git 忽略的 `Codex-Temp/`，仅供本机发布线程读取。
- 线程可以读取并使用账号密码，但不得在聊天、命令输出、日志、文档、截图、提交信息或错误报告中回显。
- 不得把凭据文件加入 Git、发布包、云端目录或交接提示词。
- 推荐由 Python `paramiko` 在本机读取文件并建立 SSH/SFTP 连接，避免把密码拼进命令行。
- 密码变更时只更新此文件；指南、提示词和项目文档只记录文件位置。
- 执行前用 `git check-ignore -v -- Codex-Temp/runtime/cloud-deployment-credentials.json` 确认仍被忽略。

## 5. 已授权的发布边界

大尾巴已授权云端发布专用线程执行以下操作：

- 使用本机私密文件中的 SSH 账号密码登录既有服务器。
- 上传经过门禁检查的发布包。
- 新建版本目录、安装本项目依赖、切换 `current` 软链接。
- 安装仓库内既有运行保护配置，重启主服务。
- 按发布前真实状态启用或停用第二层机器人服务。
- 上线失败时切回上一发布目录并恢复服务。
- 完成文档回写、本地 Git 提交和推送。

以下操作仍不在授权范围内：

- 输出、传播或提交任何密码、密钥、令牌、App Secret、Webhook 或连接票据。
- 删除历史发布目录、运行数据库、日志或秘密配置。
- 未经明确授权向飞书/WeAct 群或个人发送测试消息。
- 发布前机器人关闭却强制启用机器人。
- 绕过资产校验、健康检查或失败回滚。

## 6. 标准发布流程

### 6.1 本地状态与版本确认

```powershell
git status --short
git diff --stat
git rev-parse --short HEAD
```

确认事项：

- 保留用户的无关未提交文件，不擅自加入、移动或删除。
- 核对 `README.md`、`CHANGELOG.md`、当前版本计划、前端版本常量和后端健康接口版本。
- 若本次发布对应新版本，先完成版本号与项目文档同步。

### 6.2 本地验证

按改动范围执行最低门禁：

```powershell
npm run frontend:build
python -m pytest backend/tests -v
python tools/check_prd_consistency.py --strict
git diff --check
```

纯前端小改可按项目 `AGENTS.md` 的轻量规则缩减；版本发布、后端改动、规则改动或集中改造不得省略相应专项测试。测试失败必须先处理，不能带病发布。

### 6.3 准备暂存发布目录

优先使用项目内自动构建器，不再手工复制上一发布暂存目录：

```powershell
python tools/build_cloud_release.py
```

脚本默认先运行 `npm run frontend:build`，然后从当前项目、上线 Skill Manifest 和 `config/knowledge-qa-libraries.json` 复制运行资产，检查 `frontend/dist/index.html` 实际引用的 JS / CSS 是否存在，排除秘密、SQLite、日志和运行缓存，执行 `check_cloud_release.py`，最后输出本次独立 `release/`、UTF-8 `tar.gz` 和 SHA256。只有已经单独完成前端生产构建时，才可使用：

```powershell
python tools/build_cloud_release.py --skip-frontend-build
```

默认输出目录带构建时间和版本号；目录已存在时脚本拒绝覆盖，避免污染或破坏上一份候选包。

建议目录：

```text
Codex-Temp/cloud-deploy/<日期-版本-说明>/release/
```

发布包应包含运行所需的最小完整资产，至少包括：

- `backend/app/`
- `backend/feishu_bot_runner.py`
- 后端运行依赖清单
- `frontend/dist/`
- `business-skills/` 及所有已上线 Manifest 声明资产
- `config/project-default-settings.json`
- `deploy/`
- 云端发布检查脚本
- 正式结构化计价库、规则资产、报告模板、经验池模板和知识问答资料
- 运行所需的 README / AGENTS / CHANGELOG / PRD 上下文

严禁包含：

- `.env.local`
- `Codex-Temp/runtime/` 中的秘密、SQLite、队列、日志和缓存
- SSH 凭据文件
- 与运行无关的大体积素材或原始比赛资料

### 6.4 发布包资产门禁

```powershell
python tools/check_cloud_release.py --release-root "<暂存目录>\release"
```

任何已上线 Skill 资产缺失都必须停止。检查通过后生成 UTF-8 `tar.gz`，计算 SHA256，并在上传后与服务器端校验值比对。

### 6.5 云端发布前检查

登录后先只读检查：

```bash
readlink -f /opt/zaojiazhisuan/current
systemctl is-active zaojiazhisuan.service
systemctl is-enabled zaojiazhisuan-feishu-bot.service
systemctl is-active zaojiazhisuan-feishu-bot.service
pgrep -af feishu_bot_runner.py || true
curl -fsS http://127.0.0.1:1285/api/health
df -h /opt/zaojiazhisuan
```

记录：

- 当前软链接，作为回滚目标。
- 主服务状态。
- 第二层机器人 `enabled` 配置、systemd 状态和真实运行器数量。
- 当前健康版本和剩余磁盘空间。

### 6.6 上传与解包

1. 上传到 `/tmp/`。
2. 在服务器计算 SHA256，与本地一致后才继续。
3. 解压到新的、唯一的发布目录，不覆盖历史目录。
4. 从上一发布目录复制 `.env.local` 和 `Codex-Temp/runtime/` 到新目录。
5. 再次确认发布包没有覆盖运行秘密、知识记忆 SQLite 和机器人配置。
6. 在切换前检查新目录版本、前端产物和关键资产。

### 6.7 依赖、切换与主服务

使用既有虚拟环境安装新增依赖，然后切换：

```bash
ln -sfn "/opt/zaojiazhisuan/releases/<新发布目录>" /opt/zaojiazhisuan/current
bash /opt/zaojiazhisuan/current/deploy/install_cloud_runtime_guard.sh
systemctl daemon-reload
systemctl restart zaojiazhisuan.service
```

轮询本机健康接口，不使用一次 `curl` 的瞬时失败直接判定失败。健康接口必须返回预期版本。

若主服务未在限定时间内恢复：

1. 读取 `systemctl status`、`journalctl` 和服务错误日志。
2. 将 `current` 切回记录的上一发布目录。
3. 重新安装上一版运行保护并重启主服务。
4. 验证上一版本恢复后再报告失败原因。

### 6.8 第二层机器人条件恢复

主服务健康后读取：

```bash
curl -fsS http://127.0.0.1:1285/api/collaboration/feishu-app-bot/status
```

规则：

- `enabled=true`：执行 `systemctl enable --now zaojiazhisuan-feishu-bot.service`。
- `enabled=false`：执行 `systemctl disable --now zaojiazhisuan-feishu-bot.service`。
- 不以服务旧状态替代配置真相。
- 开启时必须验证 WeAct/飞书连接正常且 `feishu_bot_runner.py` 恰好一个。
- 关闭时必须验证服务 `inactive` 且运行器为 0。
- 不发送任何群测试消息。

随后执行：

```bash
/opt/zaojiazhisuan/venv/bin/python \
  /opt/zaojiazhisuan/current/tools/check_feishu_deployment.py \
  --mode cloud --check-health
```

### 6.9 上线验收

至少完成以下公网与远程验收：

| 检查项 | 通过标准 |
| --- | --- |
| 公网健康接口 | HTTP 200，版本号为预期值 |
| 公网首页 | HTTP 200，可加载当前 JS/CSS |
| 前端版本 | 页面或 bundle 中为预期版本 |
| 本次关键功能 | 当前 bundle 含关键标识，必要时浏览器实测 |
| 知识库检索 | `/api/knowledge/search` 返回有效结果 |
| 当前软链接 | 指向本次新发布目录 |
| 主服务 | `active` |
| 机器人 | 与 `enabled` 配置一致，运行器为 0 或恰好 1 |
| 资产门禁 | `check_cloud_release.py` 已通过 |
| 飞书部署检查 | `check_feishu_deployment.py` 已通过 |
| 秘密与运行数据 | 已继承，未进入发布包和 Git |

浏览器仍显示旧版时，先核对首页引用的 JS/CSS 文件名和资源内容，再进行强制刷新；不能只凭浏览器缓存页面判断云端未更新。

### 6.10 清理、回写与 Git

- 删除 `/tmp/` 中本次上传包，不删除历史发布目录。
- 更新 `docs/云服务器部署说明.md`：版本、发布目录、上一目录、SHA256、验证结果、机器人状态和回滚点。
- 若项目当前版本或状态变化，同步更新 README、CHANGELOG 和当前版本计划。
- 再次执行 `git status --short`、`git diff --stat`、`git diff --check`。
- 只提交本次相关文件，写清发布备注，然后推送当前分支。

## 7. 常见故障

| 现象 | 处理 |
| --- | --- |
| OpenSSH 密码登录失败或无法非交互输入 | 使用本机凭据文件和 `paramiko`，不要把密码放入命令行 |
| 上传后中文目录乱码 | 改用 UTF-8 `tar.gz`，不要使用 Windows ZIP + Linux unzip |
| `check_cloud_release.py` 报 Skill 资产缺失 | 补齐 Manifest 声明资产，禁止绕过 |
| 重启后第一次健康检查失败 | 有限轮询；持续失败则查日志并回滚 |
| 健康正常但页面仍是旧版 | 检查首页实际引用的 bundle、资源内容和浏览器缓存 |
| 主服务正常但机器人失败 | 分开检查状态接口、systemd、真实 runner 和 `1285` 环境覆盖 |
| systemd 显示 inactive 但存在 runner | 先核对真实进程，停止旧实例后再由单一 systemd 接管 |
| 知识问答或任务处理报连接 8000 失败 | 重新运行 `install_cloud_runtime_guard.sh`，确认机器人内部 API 为 `127.0.0.1:1285` |

## 8. 最终交付格式

发布线程最终必须明确报告：

1. 发布版本、Git 提交、云端发布目录、上一回滚目录。
2. 发布包 SHA256。
3. 本地构建与测试结果。
4. 公网健康、首页、当前 bundle、知识库检索结果。
5. 主服务和第二层机器人真实状态。
6. 文档、版本、CHANGELOG、README、PRD 是否更新。
7. Git 是否已提交并推送。
8. 若失败，当前是否已回滚、云端实际运行哪个版本、还需要什么人工处理。
