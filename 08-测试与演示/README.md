# 测试与演示

## 当前核心业务验收基线

当前唯一现行核心业务验收版本为 `测试-V3.1-260802/`。该目录内以下三份文件作为一组维护：

- 测试输入：`【项目例子】【测试输入】可行性研究勘察测量控制价计算 -v3.1【批注-完备】.xlsx`
- Excel 标准答案：`【答案-对应版本v3.1】【输出】-控制价计算表-20260802-0123-隐藏空行.xlsx`
- Word 标准答案：`【答案-对应版本v3.1】【输出】-控制价报告-.docx`

旧 100 行、500 行输入与答案已经归档，只可用于历史回归或专项定位，不得再称为当前核心业务验收材料。

## 验收流程

1. 使用上述 V3.1 测试输入走当前正式业务流程，不直接修改原始输入和标准答案。
2. 完成转换、批量匹配、公式刷新、风险诊断、Excel 输出和 Word 报告生成。
3. 将新生成的控制价计算表与 Excel 标准答案核对，重点检查工作表结构、有效业务行、基价 / 单价、实物工作费调整系数、技术工作费调整系数、金额公式与汇总、匹配说明、风险诊断以及应隐藏的空行。
4. 将新生成的控制价报告与 Word 标准答案核对，重点检查项目基本信息、计费依据、控制价金额及税费口径、处理结论、风险概览、逐项风险说明和文档可读性。
5. 自动化测试、前端构建、接口健康检查和 PRD 巡检全部属于技术验证，不能替代本流程。核心结果不一致时不得宣称任务完成，必须说明差异、原因和处理结论。

## 版本维护

- 新测试版本必须新建独立版本目录，并同时提供一份输入和两份对应答案；不得覆盖 V3.1 原始材料。
- 切换核心业务验收版本时，必须同步更新本文件、根目录 `AGENTS.md`、根目录 `README.md` 和相关模块 PRD。
- 同一版本的输入、Excel 答案和 Word 答案必须保持在同一目录，文件名明确标识用途和对应版本。
