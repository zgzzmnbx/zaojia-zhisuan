# HealthCare 健康仪表盘：UI 风格、图表与跨项目复用经验

## 1. 参考来源与使用边界

- 参考页面：[健康仪表盘 · HealthCare](https://claude.ai/code/artifact/caceecbd-288d-4f38-8432-b02a5270d836?org=3ffe8712-f87e-4976-bbd4-4ea21f96e79f&open_in_browser=1)
- 观察日期：2026-08-12
- 已检查页面：`总览`、`睡眠`、`身体`、`体检`、`联动`、`明细`
- 页面数据范围：睡眠 2196 晚、身体快照 19 次、方案 11 版、体检指标 234 条。
- 本文依据页面运行态的可见界面、交互控件和图表结果总结。未取得原始源码，因此“实现方式”部分是可复现同等效果的推荐方案，不宣称等同于原页面内部技术实现。
- 原页面采用深色健康数据主题；跨项目复用时应吸收信息架构、组件模式、数据语义和交互方式，不机械复制深色配色、字号或固定列数。

## 2. 一句话风格定义

> **深色分析驾驶舱 × 高密度卡片网格 × 阈值和阶段可视化 × 汇总到原始数据逐层下钻。**

这套界面的成熟之处，不是“图表多”，而是把以下四件事同时做好：

1. 先用 KPI 和信号灯回答“现在怎么样”。
2. 再用目标区间、方案阶段和长期趋势回答“如何变化”。
3. 用相关性、滚动均值和版本对照回答“哪些因素可能有关”。
4. 最后保留可搜索、可筛选、可导出的原始明细，回答“依据是什么”。

## 3. 信息架构

### 3.1 六级视图分工

| 页面 | 核心任务 | 主要组件 | 可复用场景 |
| --- | --- | --- | --- |
| 总览 | 快速判断当前状态和长期方向 | KPI 卡、长期趋势、体检信号灯、年度趋势、双轨方案时间线 | 管理驾驶舱、项目总览、经营总览 |
| 睡眠 | 查看一个专业域的时间规律 | 年份筛选、月度折线、年×月热力图、堆叠面积图、分组柱图 | 运营分析、活跃度、结构组成、周期规律 |
| 身体 | 把结果与方案版本、目标值联系起来 | 版本背景分区、目标线、双指标趋势、围度小图 | 项目版本、产品迭代、质量目标、成效追踪 |
| 体检 | 找到异常并回查全部指标 | 参考区间小多图、异常点、全量指标表、关键/异常筛选 | 质量门禁、风险监控、系统健康、合规检查 |
| 联动 | 分析指标之间的关系 | 相关性矩阵、散点图、趋势线、滚动均值、方案对照表 | 诊断分析、实验分析、影响因素研究 |
| 明细 | 回到所有原始记录 | 数据集分段、搜索、排序、列筛选、内层滚动、CSV 导出 | 审计、数据复核、运营明细、项目/任务/版本台账 |

### 3.2 推荐的通用分层

```text
总览层：状态、KPI、异常、主趋势
    ↓
专业分析层：按主题或业务域组织图表
    ↓
联动诊断层：相关性、对照、版本效果
    ↓
原始明细层：搜索、筛选、排序、导出、审计
```

这比“在一个页面连续堆几十张图”更容易理解，也便于按权限、性能和用户角色拆分。

## 4. UI 视觉语言

### 4.1 页面骨架

- 顶部采用固定标题区和分段式页面导航，页面滚动后仍可快速切换视图。
- 主体使用全宽分析网格，常见为两列；信息同质且卡片较小时可三列。
- 卡片之间保持稳定间距和统一基线，避免某张图因标题较长或图例较多而破坏整行节奏。
- 原始数据表放在独立大容器内，表格自己承担横向和纵向滚动，页面主壳不横向溢出。
- 页面末尾持续标明数据来源、日期范围和构建口径，使漂亮图表仍然可追溯。

### 4.2 卡片结构

每张图表卡遵循相同解剖：

```text
┌──────────────────────────────────────┐
│ 主标题                     当前值/状态 │
│ 数据口径、时间范围、交互提示           │
│                                      │
│              图表主体                 │
│                                      │
│ 图例 / 目标线说明 / 口径补充           │
└──────────────────────────────────────┘
```

统一结构的价值在于：用户学会一张卡后，就能读懂所有卡；开发侧也可以复用 `ChartCard`，而不是每张图重新写标题、留白、错误态和图例。

### 4.3 色彩语义

原页面的视觉色值以下仅作近似观察。复用时应映射为项目自己的语义 token，不应在组件中直接复制色值。

| 语义 | 原页面表现 | 通用使用规则 |
| --- | --- | --- |
| 页面背景 | 接近黑色的深灰 | 只决定主题，不承载业务含义 |
| 面板表面 | 比背景略亮的炭灰 | 依靠 1px 边界区分层级，不依赖厚阴影 |
| 主数据 | 蓝、蓝紫、青绿 | 用于中性趋势和主要系列 |
| 正常 | 绿色文字、绿色徽标、低透明绿色区间 | 仅用于明确通过、达标、正常 |
| 提醒 | 琥珀或橙色 | 用于边界、待关注、轻度异常 |
| 异常 | 红色文字、红色徽标、异常点 | 必须同时提供图标或文字，不能只靠颜色 |
| 目标 | 细绿线或灰线 | 同时显示目标名称和数值，避免用户猜测 |
| 方案阶段 | 低透明度棕/橙背景带 | 背景只作上下文，不抢主数据线 |

### 4.4 三层 token 转译

跨项目复制时，应把视觉观察转成“原始值 → 语义 → 组件”三层 token：

```css
/* Primitive：项目可替换的基础色 */
:root {
  --viz-neutral-950: #0b0d0c;
  --viz-neutral-900: #161916;
  --viz-neutral-700: #343834;
  --viz-neutral-100: #f3f5f3;
  --viz-blue-500: #5b8def;
  --viz-green-500: #4e9f74;
  --viz-amber-500: #b98533;
  --viz-red-500: #c4514e;
}

/* Semantic：表达业务含义 */
:root {
  --viz-page-bg: var(--viz-neutral-950);
  --viz-surface: var(--viz-neutral-900);
  --viz-border: var(--viz-neutral-700);
  --viz-text: var(--viz-neutral-100);
  --viz-series-primary: var(--viz-blue-500);
  --viz-status-success: var(--viz-green-500);
  --viz-status-warning: var(--viz-amber-500);
  --viz-status-danger: var(--viz-red-500);
}

/* Component：允许单组件调整 */
:root {
  --metric-card-bg: var(--viz-surface);
  --metric-card-border: var(--viz-border);
  --metric-card-radius: 10px;
  --chart-grid-color: color-mix(in srgb, var(--viz-border) 65%, transparent);
  --reference-band-success: color-mix(in srgb, var(--viz-status-success) 14%, transparent);
}
```

说明：上述色值用于解释 token 结构，不是要求其他项目照抄。亮色项目只需替换语义层，图表和组件不应重写。

### 4.5 字体、密度和数字

- 页面标题、卡片标题、正文、辅助说明保持稳定层级，不通过大量不同字号制造层次。
- 数字使用 `font-variant-numeric: tabular-nums`，便于纵向比较和表格对齐。
- 单位紧跟数字但降低视觉权重；坐标轴必须标出单位。
- 图表密集不等于文字可以过小。通用业务文字建议不小于 12px，中文连续文本优先 13px-14px。
- 表格数字右对齐，文字左对齐，状态居中，操作靠右。

### 4.6 形状与动效

- 卡片采用中等圆角、1px 细边框、极弱或无阴影。
- 分段控件使用胶囊底座加浅色选中块，选中态清楚但不高饱和。
- 状态徽标同时具备颜色、文字和符号，如 `✓ 正常`、`▲ 偏高`。
- 动效应服务于数据更新和下钻反馈，避免整页卡片浮动、缩放或持续脉冲。
- 支持 `prefers-reduced-motion`；关闭图表入场动画后不能影响数据阅读。

## 5. 核心组件目录

| 组件 | 原页面特征 | 建议抽象 |
| --- | --- | --- |
| 页面导航 | 总览/睡眠/身体/体检/联动/明细分段切换 | `DashboardTabs`，路由或状态驱动，保留筛选上下文 |
| 主题开关 | 自动/亮/暗切换 | `ThemeToggle`，只改语义 token |
| KPI 卡 | 强数字、单位、日期、目标或变化提示、左侧语义色条 | `MetricCard`，统一 `value/unit/detail/tone` |
| 图表卡 | 标题、说明、当前值、图表、图例、口径 | `ChartCard`，统一加载、空态、错误态和高度 |
| 信号灯 | 指标名、当前值、单位、正常/异常徽标 | `SignalList`，强调“需要行动”的信息 |
| 周期筛选 | 全部和年份分段按钮 | `PeriodFilter`，可与全局筛选同步 |
| 方案阶段条 | 两条横向版本时间轴 | `PhaseTimeline`，CSS Grid 实现即可 |
| 来源脚注 | 数据源、起止日期、同步时间、限制 | `DataProvenance`，所有正式看板应保留 |

### 5.1 KPI 卡标准结构

```ts
type MetricCardProps = {
  label: string;
  value: number | string;
  unit?: string;
  observedAt?: string;
  detail?: string;
  tone?: "neutral" | "info" | "success" | "warning" | "danger";
  onClick?: () => void;
};
```

一张 KPI 卡只回答一个问题。若卡片同时展示当前值、长期目标、短期目标和变化值，应通过两行辅助说明组织，不能把所有内容都放成同级大字。

## 6. 图表种类与复用规则

### 6.1 图表选型总表

| 图表类型 | 原页面用途 | 适合表达 | 推荐实现 | 主要风险 |
| --- | --- | --- | --- | --- |
| KPI 指标卡 | 当前体重、体脂、腰围、睡眠、方案版本 | 当前状态和目标差距 | 普通组件，不依赖图表库 | KPI 过多导致首屏失焦 |
| 长期折线＋目标线 | 十年体重、年度睡眠 | 长周期方向和目标 | `LineChart + ReferenceLine` | 稀疏数据不应画成连续精确轨迹 |
| 折线＋正常区间 | 体检指标趋势 | 当前值是否进入允许范围 | `ReferenceArea + Line` | 区间必须有正式来源 |
| 折线＋方案背景分区 | 体重/体脂与方案版本 | 不同版本阶段与结果变化 | 多个 `ReferenceArea` 或 SVG 背景带 | 阶段与结果同时变化不等于因果 |
| 月度密集折线 | 睡眠时长、质量 | 高频波动和长期趋势 | 折线＋点选下钻 | 点过多时必须聚合或抽样 |
| 年×月热力图 | 睡眠质量热力 | 周期性、缺失、活跃程度 | CSS Grid、SVG 或 ECharts heatmap | 色阶需附数值范围，缺失不能当作零 |
| 堆叠面积图 | 深睡/REM/浅睡/清醒结构 | 总量与组成随时间变化 | `AreaChart`，统一 `stackId` | 只适合同单位、可相加的组成项 |
| 同单位双折线 | 入睡/起床时间、胸围/臀围 | 两个同量纲指标的同步变化 | 双 `Line` | 不同单位禁止共用同一纵轴 |
| 分组柱状图 | 工作日 vs 周末 | 两组对象在少量指标上的比较 | `BarChart` 分组柱 | 指标过多时标签拥挤 |
| 稀疏柱状图 | 内脏脂肪等级 | 离散测量和等级变化 | 柱状或点图 | 稀疏值不宜暗示连续采样 |
| 小多图 | 多项体检指标 | 同结构、多指标、快速扫异常 | Small Multiples，每图独立范围 | 不能为了三列布局压缩文字和坐标 |
| 相关性矩阵 | 睡眠、步数、心率等关系 | 多指标线性相关的初步筛查 | CSS Grid/SVG，单元格显示 `r` | 相关不等于因果；样本数必须可见 |
| 散点＋趋势线 | 步数与睡眠质量 | 两变量分布、离群点、线性方向 | `ScatterChart`＋计算回归线 | 样本聚集时透明度、采样和抖动要处理 |
| 滚动均值双折线 | 减脂期身体响应、睡眠输入 | 平滑短期噪声，比较同步方向 | 预先计算 7/14/30 日均 | 必须显示窗口长度，不隐藏原始波动事实 |
| 双轨阶段时间线 | 饮食和运动方案版本 | 两条并行版本轨迹 | CSS Grid/Flex，不必使用图表库 | 阶段起止和“至今”要有明确数据 |
| 版本效果对照表 | 各方案下发生了什么 | 版本、周期、样本和成效横向比较 | 语义表格 | 样本过少时不能给出强结论 |

### 6.2 目标区间图

目标区间是本参考最值得吸收的模式之一。它把“数值变化”提升为“是否达标”。

推荐数据结构：

```ts
type ReferenceBand = {
  label: string;
  min?: number;
  max?: number;
  source: string;
  severity: "success" | "warning" | "danger";
};
```

Recharts 等价实现：

```tsx
<ReferenceArea y1={range.min} y2={range.max} fill="var(--reference-band-success)" />
<ReferenceLine y={target} stroke="var(--viz-status-success)" label={`目标 ${target}`} />
<Line dataKey="value" stroke="var(--viz-series-primary)" />
```

硬规则：

- 没有正式阈值、业务目标或统计基线时，不画绿色“正常区间”。
- 区间必须能追溯到制度、配置、项目目标或经确认的统计口径。
- 越界点使用形状或图标增强，不只改变颜色。

### 6.3 阶段背景图

方案阶段背景适合说明“某次版本变更发生在何时”，而不是证明“这个版本导致了结果”。

```ts
type PhaseBand = {
  id: string;
  label: string;
  start: string;
  end?: string;
  category: string;
  version?: string;
};
```

建议同时显示：

- 阶段名称和版本号。
- 开始、结束或“至今”。
- 该阶段的样本量。
- 关键指标的阶段均值或变化值。
- “仅供阶段对照，不代表因果”的提示。

### 6.4 小多图

小多图适合几十个同类指标快速扫异常。每张小图的结构必须一致：

```text
指标名称
最近日期 · 当前值 · 状态
参考区间背景
历史折线
异常点
```

布局建议：

- 宽屏最多三列，中等工作区两列，窄屏一列。
- 卡片高度统一；标题和单位不截断。
- 每张图独立纵轴，但必须明确刻度，不能让相同视觉斜率被误认为相同变化幅度。
- 支持“只看异常”和“只看关键指标”。

### 6.5 相关性矩阵和散点图

它们适合分析人员，不适合直接成为管理结论。

必须同时显示：

- 样本量 `n`。
- 相关系数类型，如 Pearson 或 Spearman。
- 数据时间范围和缺失处理方式。
- 散点分布，而不只显示一个系数。
- “相关不等于因果”的固定说明。

当样本少、时间序列存在趋势或多个变量共同变化时，应避免用相关系数做自动决策。

## 7. 表格种类

### 7.1 信号灯列表

这是一种“轻表格”，比饼图更适合表达需要处理的事项。

| 字段 | 示例 | 规则 |
| --- | --- | --- |
| 指标 | 低密度脂蛋白 LDL-C | 保留全称和缩写 |
| 当前值 | 3.22 | 数字右对齐 |
| 单位 | mmol/L | 降低视觉权重但不可省略 |
| 趋势 | ↑ / ↓ | 只有存在可比较前值时显示 |
| 状态 | `▲ 偏高`、`✓ 正常` | 文字＋符号＋颜色三重表达 |
| 日期 | 最近体检 2026-07-10 | 明确数据新鲜度 |

适合：风险中心、待办中心、系统健康、合规门禁、需要人工处理的项目列表。

### 7.2 版本效果对照表

原页面用方案版本、时间区间、体重斜率、平均睡眠和平均质量回答“每版发生了什么”。

跨项目通用字段：

| 维度 | 推荐字段 |
| --- | --- |
| 版本 | 方案、模型、Skill、规则或产品版本 |
| 周期 | 开始日期、结束日期、至今 |
| 样本 | 项目数、任务数、记录数 |
| 输入 | 工作量、调用量、投入时长 |
| 结果 | 完成率、成功率、匹配率、质量分 |
| 风险 | 异常数、退回数、失败数 |
| 变化 | 相对上一版本的差值和方向 |

表内红绿只能表达已确认的好坏语义；例如“数量上升”可能代表增长，也可能代表风险增加，不能自动一律标绿。

### 7.3 全量指标表

体检页的全量表承担“图表异常的完整证据库”。核心特征：

- 顶部有搜索、只看关键、只看异常。
- 表头固定，表体独立滚动。
- 每列可排序或筛选。
- 同时展示数值、单位、参考范围、状态、分类、关键标记和来源机构。
- 状态徽标可扫读，原始数值仍保留。

### 7.4 原始明细表

明细页使用“睡眠｜身体｜方案”分段切换数据集，并显示每类总量、快速搜索和 CSV 导出。

跨项目可转译为：

```text
项目 128 个｜任务 476 次｜版本 83 版
```

建议实现：

- 数据集切换不丢失各自的搜索、排序和滚动位置。
- 超过 500 行使用服务端分页或虚拟滚动。
- 横向滚动只发生在表格容器中。
- 第一列或主键列可固定；操作列可按业务需要固定在右侧。
- 导出必须使用当前筛选口径，并在文件名中包含数据集和导出日期。
- 表格值与图表聚合必须来自同一真源和同一过滤条件。

## 8. 交互经验

### 8.1 筛选与下钻

- 总览筛选影响 KPI、图表和表格，不能各自维护不同口径。
- 点击月份或数据点可下钻到该年/月/日的明细。
- 点击异常卡可自动启用“只看异常”。
- 点击方案阶段可筛选对应版本及周期。
- 当前筛选条件应以 chip、分段选中态或明确文字持续可见。

### 8.2 图例

原页面图例具有按钮语义，可用于显示/隐藏系列。推荐实现时应使用真实 `button` 或 `role="switch"`，提供：

- 键盘焦点。
- `aria-pressed` 或 `aria-checked`。
- 当前系列名称、状态和次序。
- 关闭系列后仍能恢复，不靠重新加载页面。

### 8.3 状态完整性

每个图表和表格都必须具备：

- 加载态：稳定高度骨架，不让页面跳动。
- 空态：说明是“无数据”“筛选后无数据”还是“未运行”。
- 错误态：单卡失败，不导致整页白屏。
- 过期态：说明最近更新时间和数据是否仍可信。
- 权限态：没有权限时不泄露统计和明细。

### 9.2 数据模型

```ts

  category?: string;
  status?: string;
```

所有聚合接口应返回 `generated_at`、时间范围、样本量、缺失量和口径说明。前端不应从已经格式化的字符串反推数字。

### 9.3 图表库选择

| 场景 | 优先方案 | 原因 |
| --- | --- | --- |
| 常规折线、柱状、面积、环图 | Recharts | React 集成简单，适合业务看板 |
| 高密度散点、数千点热力图 | ECharts 或 Canvas | 避免大量 SVG 节点导致卡顿 |
| 相关性矩阵 | CSS Grid 或 SVG | 单元格需显示系数并可聚焦 |
| 版本时间线 | CSS Grid | 结构明确，不需要图表库 |
| 数据表 | TanStack Table＋虚拟滚动 | 排序、筛选、列状态可复用 |

### 9.4 性能

- 页面级图表按需加载；隐藏页面应卸载图表子树，不让响应式图表在零尺寸容器中持续计算。
- 2196 个以上时间点不要全部以高成本动画绘制；总览先聚合到月/年，下钻后再看日数据。
- 散点超过约 1000-2000 个时优先 Canvas、透明度和采样策略。
- 表格数据采用后端分页或虚拟滚动，不一次渲染全部单元格。
- 聚合、滚动均值、相关系数和回归线尽量在数据层预计算，避免每次组件渲染重复计算。
- 图表 tooltip、legend formatter、筛选回调使用稳定引用，避免整页图表反复重绘。

### 9.5 响应式

优先依据看板容器宽度而不是整个浏览器宽度切换布局，特别适合存在左右侧栏、AI 助手或嵌入宿主的产品。

## 12. 值得吸收与不应照搬

### 12.1 值得吸收

- 汇总、专业分析、联动、原始明细四层信息架构。
- 目标区间和阶段版本同时出现在趋势图中。
- “当前值＋日期＋状态＋历史趋势”的小多图结构。
- 信号灯列表优先展示需要行动的异常，而不是只给一张分布图。
- 图表点击下钻到同口径明细。
- 版本效果表同时展示周期、样本和结果。
- 页面底部明确数据来源、日期范围和限制。
- 表格具备搜索、筛选、排序、内部滚动和导出。

### 12.2 不应照搬

- 不因为参考页好看就把其他项目全部改成深色主题。
- 不把所有图表塞进主看板；管理用户不需要先理解相关性矩阵。
- 不在没有正式依据时绘制绿色正常区间或目标线。
- 不将不同单位的指标强行放在同一纵轴比较。
- 不把相关性、同时变化或版本上线后的改善描述为因果结论。
- 不为了保持三列而压缩卡片标题、单位、图例和辅助说明。
- 不把缺失值当作零，也不把“未运行”当作“无风险”。
- 不让动态图表替代原始表格、审计记录和数据来源。

## 13. 交付验收清单

### 数据真实性

- [ ] KPI、图表、表格使用同一筛选口径。
- [ ] 显示数据起止日期、最近更新时间和样本量。
- [ ] 缺失、未知、未运行和零值严格区分。
- [ ] 目标线和参考区间有可追溯来源。
- [ ] 版本阶段有真实起止时间和版本号。
- [ ] 相关性图显示样本量并声明不代表因果。

### 视觉与可读性

- [ ] 页面标题、卡片标题、正文、辅助说明层级统一。
- [ ] 中文业务文字不因图表密度被压到不可读字号。
- [ ] 数字使用等宽数字特性，单位完整。
- [ ] 状态不只依赖颜色，包含文字、图标或形状。
- [ ] 卡片高度、标题基线、图例和坐标留白一致。
- [ ] 深色和亮色主题均满足文字、图形和焦点对比度。

### 交互与无障碍

- [ ] 页面导航、图例、筛选和表格操作可键盘使用。
- [ ] 当前页、当前筛选、图例开关状态可被辅助技术识别。
- [ ] 图表提供 `aria-label` 或同口径文本摘要。
- [ ] 点击图表下钻后提供明确返回路径。
- [ ] 加载、空、错误、过期和权限状态完整。
- [ ] 支持减少动态效果。

### 性能

- [ ] 隐藏图表被卸载或暂停，不在零尺寸容器持续计算。
- [ ] 高频数据在总览层先聚合，下钻后再显示细粒度。
- [ ] 大表分页或虚拟滚动。
- [ ] 大散点/热力图选择 Canvas 或受控采样。
- [ ] 切换筛选后不重复请求不受影响的数据。
- [ ] 浏览器控制台无尺寸、溢出、键值重复或无障碍告警。

## 14. 最终经验结论

这套 HealthCare 仪表盘最值得跨项目复用的不是“深色卡片”，而是以下设计公式：

```text
当前状态
+ 目标/参考区间
+ 版本/阶段上下文
+ 专业域趋势
+ 异常优先
+ 相关性只作诊断
+ 原始数据可追溯
= 可管理、可解释、可审计的数据看板
```

后续新项目在采用本经验时，应先回答三个问题：

1. 用户首先要做决策，还是首先要探索数据？
2. 哪些阈值和状态具有正式业务依据？
3. 用户看到结论后，能否一键回到同口径明细和来源？

只有三个问题都能回答，图表才是在增强决策；否则只是把数据装饰成图形。
